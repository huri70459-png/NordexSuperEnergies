Section 3 · Risks, testing, migration, rollout

Final design section before the written spec. Approve to lock full design.

Risks & mitigations

  • Cinematic + Arctic Trust clash — Motion only on flagship chapters; chrome stays quiet.
  • Misnamed legacy assets — Migrate by magic-byte first; never trust extensions.
  • Lead form without backend — Explicit success UX + stub; ponytail: ceiling = no CRM until API exists.
  • Brand / legal names — “Nordex Super Energies” treated as client brand fiction unless you supply legal copy; no false claims beyond existing draft.
  • Figma drift — Generate Figma from built UI at end of Phase 1, not before tokens stabilize.

Migration order (implementation)

  1. Scaffold Next.js + Tailwind v4 + shadcn under project root
  2. Move assets to public/assets/ with correct names
  3. Extract legacy HTML → typed src/content/*
  4. Shell: layout, header, footer, tokens
  5. Routes in funnel order: Contact form primitives → Home → Turbines → Services → Company → Sustainability
  6. Cinematic motion pass + reduced-motion
  7. SEO metadata + a11y pass
  8. Figma generate for Home / Turbines / Contact + tokens
  9. Remove obsolete root files; add .gitignore

Testing (minimum bar)

  • Typecheck + production build
  • Form validation unit (zod schema self-check)
  • Manual keyboard path: nav → contact → submit success
  • Chrome DevTools: mobile + desktop smoke, console clean
  • Reduced-motion smoke

Out of Phase 1

  • CRM / email provider, Sanity CMS, i18n, auth portal
  • Hyperframes promo film (Phase 2 asset)

Success criteria

  • 6 routes live, lead form converts (UX), tokens consistent
  • Legacy broken filenames gone
  • Figma file mirrors system
  • Looks institutional (Arctic Trust), moves cinematically where intended
