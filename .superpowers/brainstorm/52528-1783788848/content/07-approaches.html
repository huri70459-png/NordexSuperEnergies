Implementation approaches

How we build Phase 1

1

Typed content modules + App Router (recommended)

Pros: Type-safe, no CMS ops, fast, content modeling principles without infrastructure, perfect for Figma-from-code.
Cons: Non-dev content edits need a PR.
Rejected alternative: Sanity day-one — rejected as YAGNI for lead-gen Phase 1.

2

MDX pages + shared components

Pros: Editorial feel, easy long-form.
Cons: Weaker for specs/tabs/forms; more glue; worse for strict design system pages.

3

Headless CMS from day one

Pros: Editor workflows, future omnichannel.
Cons: Auth, schemas, env, draft/publish — delays visual quality. Phase 2+.
